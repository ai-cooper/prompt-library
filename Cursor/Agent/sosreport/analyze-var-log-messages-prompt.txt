You are a senior Linux SRE. Analyze the system log file /var/log/messages.

Goals:

1. Identify the top 5 incident candidates (errors/warnings/anomalies) with timestamps and host/process context.
2. Detect repeating patterns (same error recurring, bursts, periodic failures) and infer likely triggers.
3. Correlate related log lines across processes (e.g., kernel ↔ systemd ↔ network ↔ storage).
4. Provide a root-cause hypothesis for each incident candidate, with confidence (High/Med/Low).
5. Provide a next-action checklist: exact commands to run and what evidence each command would confirm/deny.

Constraints & Assumptions:
- Do not assume the issue is one thing; consider multiple plausible causes.
- Prefer evidence from logs. If evidence is missing, explicitly say what’s missing.
- Pay attention to: kernel messages, OOM, soft lockups, I/O errors, NIC link flaps, time sync issues, authentication failures, SELinux AVC, filesystem errors, service restarts, and hardware RAS/ECC hints.

Output Format:
- Executive Summary (<=10 lines)
- Timeline: earliest→latest key events (timestamp, component, severity)
- Findings (Top 5): for each
	- Evidence (exact log excerpts with timestamps)
	- Pattern (frequency, burst window)
	- Hypothesis + confidence
	- Impact (what likely broke)
	- Next actions (commands + expected signals)
